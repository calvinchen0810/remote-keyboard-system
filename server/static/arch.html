The mixed runner dispatches directly to serial objects; it does not call its own HTTP routes. OCR resolves script-local variables before KBD TYPE. IMAGE_MOVE searches fresh frames and moves without clicking; CLICK/DBLCLICK are separate MSE steps. Clear commands bypass the execution queue. See Visual & Scripts for full behavior and limits.

FIFO / Active-Script Visual Conditions

POST /script/run imports and queues a job, including jobs with EVT gates. Submit A, wait for its HTTP response, then submit B and C to guarantee A -> B -> C. Concurrent requests follow server-lock acquisition order; a successful response does not mean execution has completed.

  • Conditions can only be activated by the active script; the UI and API expose no manual ARM/DISARM controls. TEST performs a one-frame comparison without enabling continuous monitoring. Later scripts cannot bypass the active job's event wait.
  • At each job boundary: disarm conditions, remove old IMG events, and reset hit counts, edge state and cooldown. Identical images and shared existing condition IDs are supported; the next job requires new post-activation captures, not disappearance/reappearance.
  • Each capture generation counts at most once. A stalled camera cannot repeatedly satisfy min_hits using the same cached frame.
  • Active IMG events enter EventBus without waiting for _script_control_lock held by a later import. Ownership is checked atomically under the EventBus lock. Legacy EVT Pool release stays serialized; new jobs do not enter that pool.
  • EVT/IMG waits have no timeout or countdown and never automatically pause. Conditions stay armed while waiting and later jobs stay queued. PAUSE / POST /script/pause manually suspends at safe checkpoints and disarms current conditions; RESUME / POST /script/resume discards paused-period gate events, rearms fresh runtime and continues without replaying earlier actions.
  • GET /script/status includes manual pause metadata and unique pause_id; running stays true while suspended. RESUME must echo pause_id; missing/stale IDs or duplicate resume return 409. WebSocket script_paused/script_resumed and status polling restore the state after reload; superseded polls are ignored. Stop/clear cancels the job and discards the queue. Existing dispatched hardware actions cannot be recalled. OCR/image search retain their bounded safety timeouts and do not automatically pause. loop: true otherwise retains its turn until stopped.

GET /script/status returns running, queued, waiting, pause and legacy pending state. The right-hand FIFO Queue panel replaces EVT Pool and the duplicate Progress panel: it shows the active job name, Running/Waiting/Paused state, current step, waiting/paused event and later queued count excluding the active job. It is a read-only global summary, not event history or a queue editor. Detailed progress remains in Execution Status. Status polling restores waiting state after reload and WebSocket updates reflect transitions; stop/clear resets it. Auto-attach happens when a job becomes active, not when it is submitted.

Clear Command / Workspace Reset

Send the following object to POST /script/run; it is handled as a management command, not a queued script:

{"command":"clear","targets":["snapshots","conditions","scripts"]}

Cancel and await the runner; discard queued scripts, EVT Pool and buffered events; persist empty conditions and clear match runtime; then clear snapshots. Broadcast workspace_cleared so connected browsers reset Script Editor, visual lists, progress and keyboard lock.

All three targets are required; unknown/duplicate/partial targets or extra script fields return 400 before mutation. Repeating on empty state succeeds with zero counts. If persistence fails, return 500: scripts are already stopped but conditions/snapshots are retained for retry. Camera/serial connections, servo configuration and logs are preserved. Already transmitted hardware actions cannot be recalled.

Four-Digit OCR / Script Variables

SNAP selects a normalized ROI; runtime reads the same area from fresh camera/capture-card frames, not from the setup SNAP. Settings live inline in an ocr step and survive SNAP deletion. The default is two agreeing distinct captures within 5000ms.

{"type":"ocr","roi":[0.05,0.1,0.2,0.08],"variable":"digits","timeout_ms":5000,"stable_hits":2}
{"type":"kbd","cmd_type":"TYPE","text":"${digits}"}
{"type":"kbd","cmd_type":"KEY","key":"ENTER"}

Accept exactly four ASCII digits; preserve leading zeros such as 0037. Variables are local to one script iteration and the target variable is cleared before OCR. Missing/malformed placeholders or failed OCR abort before later keyboard transmission. Substitution applies only to structured KBD TYPE text, not raw cmd/KEY/COMBO.

OpenCV preprocessing + pytesseract require an external Tesseract executable with English trained data. TESSERACT_CMD configures a custom executable path; PATH and standard Windows install directories are also checked. The EXE includes the Python wrapper, not the external executable/DLLs/trained data. Missing OCR prerequisites do not disable other features; real capture accuracy still needs calibration.

POST /visual/ocr/test performs recognition without assigning script variables: 422 invalid settings, 503 unavailable engine, 408 timeout. Export schema_version 3 identifies OCR unless an IMAGE_MOVE step requires version 5.

IMAGE_MOVE / Locate Center and Move Only

SNAP MOV selects a cropped PNG template. A mse step with action: IMAGE_MOVE embeds it inside image_move, with frame dimensions, search ROI, threshold, timeout and stable samples, but no mouse button. Export/import uses schema_version: 5; no SNAP ID or IMG condition is required.

Runtime: search fresh captures -> reject multiple candidates -> confirm stable center -> convert to HID 0..32767 -> MOUSE:ABS x y -> require OK. It never clicks automatically. Add a separate MSE CLICK or DBLCLICK step with L/R/M; its delay controls the interval. Movement failure prevents later steps. Low-detail templates, ambiguity, timeout or an aspect-ratio change abort the job. IMAGE_CLICK is removed, not an alias; old scripts must be recreated. No Pro Micro firmware change is required.

  • Default full-frame search ROI [0,0,1,1], threshold 0.92, stable_hits 2, timeout_ms 5000. Narrow the search area to resolve duplicates instead of choosing arbitrarily.
  • Template scales proportionally when capture resolution changes; the first version targets one complete Windows desktop with no crop/black bars. Stable layout and single-display mapping are prerequisites.
  • allow_send is checked inside KeyboardSerial's serial lock, including immediately before a write, so cancelled queued sends cannot later move/click. Commands already sent cannot be undone.
  • Template-selection versions reject stale replies. Save and Test are mutually exclusive, and closing/resetting the modal aborts outstanding browser requests.

Windows click-target acceptance page has nine distinct targets and records received coordinates. The page itself sends no serial commands. Physical Windows/capture-card accuracy remains a separate user-run acceptance step; software/browser tests do not prove real HID accuracy.

Pro Micro / Relative + Absolute HID

ATmega32U4 Pro Micro uses stock Keyboard/Mouse plus HID-Project 2.8.4 AbsoluteMouse (report ID 7). Nano_KB still forwards complete lines at 38400 without interpreting them. Select the actual Pro Micro board/voltage/clock in Arduino IDE; Nano/Uno is not a compatible build target.

CAPS reports CAPS ABS_MOUSE=1 ABS_RANGE=0..32767, followed by the normal OK. MOUSE:ABS 16384 16384 moves to the center without clicking. Firmware validates both coordinates before movement and maps 0..32767 to the library's signed API; startup sends no absolute positioning report.

Commands must enter through Nano_KB -> Pro Micro Serial1. Pro Micro USB serial is still an EVT input/debug channel, not a HID command input. Relative MOVE/CLICK/SCROLL and keyboard commands remain unchanged. UI MOVE_TO still maps to relative MOUSE:MOVE and is not the absolute positioning interface.

Script Editor / SNAP Pool

  • SNAP metadata (thumbnail, ID, delete) occupies the first row; CON / OCR / MOV are three equal-width buttons on the second row, retaining their condition/OCR/image-move actions and tooltips.
  • SRV Servo ID selector is 44px wide so the number and native arrow fit.
  • KBD COMBO's second key dropdown includes F10; the first modifier dropdown and final key field remain separate and unchanged.
  • KBD TYPE offers earlier OCR variables and inserts literal ${digits} placeholders. Import materializes OCR defaults; IMAGE_MOVE settings/templates are portable.
  • Shared ROI modal preserves the source aspect ratio, supports pointer/touch selection and rejects stale responses after close/reset or a new selection.

Read-Only Execution Status / Draft Isolation

Execution Status reuses Edit's compact TYPE / DELAY / PARAMS table, colored type badges, toolbar styling and bottom progress strip. The job selector is single-row; readonly parameter fields are text elements, not disabled controls. Status markers replace drag/delete controls. Only the current active step expands condition/result/error detail; other steps and queued previews remain compact. Completed/failed steps, not the current waiting index, determine progress percentage.

Script Editor has independent Edit and Execution Status tabs. Runtime notifications never assign to the local steps draft. KBD TYPE is displayed in full, HTML-escaped and unmasked. The optional Name field is included in submitted/exported JSON; every submission receives a generated job_id, even when the same request object is reused.

Follow Active tracks the FIFO head; selecting a queued job previews immutable submitted parameters without arming conditions, changing order or executing. There are no editing, drag/reorder, delete or rerun controls and no history store. Current/completed/failed/pending rows, iteration, waiting/paused/recognizing/locating phase, OCR values and IMAGE_MOVE results are shown. EVT/IMG displays no timeout; remaining time applies only to bounded recognition/search.

Condition details include name, ROI, thumbnail when available, score/threshold and hits. Queued previews are inactive and never borrow another job's runtime. STOP and PAUSE ACTIVE / RESUME ACTIVE control the active job, not the selected preview.

GET /script/status includes lightweight runtime metadata; WebSocket script_runtime carries session/revision snapshots. GET /script/jobs/{job_id} returns read-only steps and condition detail without large template payloads. Polling refreshes metrics/deadlines; old sessions, stale requests and old preview content are rejected/cleared. Reload/reconnect restores live work, while completed/stopped/cleared jobs are removed.

Verify with tools/test_script_runtime.py, runtime cases in tools/test_clear_command.py, and tools/test_script_editor.cjs. Confirm full TYPE is readable as text, draft is unchanged after queued previews and stop, and condition runtime stays isolated. Physical hardware is not required for these isolated tests.
